CI/CD ДЛЯ ДОМАШНЕГО N100 — КОНТЕНТ-ЗАВОД

Схема:
Изменения в main -> GitHub проверяет код -> собирает три Linux/amd64-образа
-> сохраняет их в GHCR -> runner на N100 скачивает образы и обновляет Docker.
Домашнему компьютеру достаточно исходящего доступа к GitHub и GHCR.
Открывать SSH/порты маршрутизатора для CI/CD не нужно.

ОДИН РАЗ В GITHUB

1. Размести актуальную версию openshorts в своём приватном репозитории.
   Корнем репозитория должна быть папка openshorts: рядом лежат app.py,
   dashboard/, deploy/ и .github/workflows/ci-cd.yml.
   Не добавляй .env, output/, uploads/, базу аккаунтов и личные API-ключи.
   В исходном проекте уже настроен remote:
   https://github.com/A-m-u-r/content-fabric-openshorts-private
   Workflow запускается для main. Изменения других веток проверяются через PR в main.

2. В Settings -> Actions -> Runners -> New self-hosted runner выбери ОС N100.
   Выполни на N100 актуальные команды регистрации, показанные самим GitHub.
   Добавь runner пользовательскую метку content-fabric.
   Устанавливай runner для этого приватного репозитория.
   Официальная инструкция:
   https://docs.github.com/en/actions/how-tos/manage-runners/self-hosted-runners/add-runners

ОДИН РАЗ НА N100

3. Установи Docker с Compose и Python 3.11 или новее.
   Команды docker compose version и python --version должны работать
   под тем же пользователем, от которого запущен runner.
   На Ubuntu может понадобиться пакет python-is-python3.
   Рекомендуемый вариант: Ubuntu 24.04, Docker Engine и runner как служба.
   Пользователь runner должен иметь доступ к Docker.
   Если используется Windows: нужны Linux containers, запущенный Docker Desktop
   и runner под пользователем с доступом к Docker Desktop.
   Порты 5175 и 8000 должны быть свободны.

4. Выбери постоянную папку данных, отдельную от рабочей папки runner:
   Ubuntu: /home/ИМЯ_ПОЛЬЗОВАТЕЛЯ/content-fabric-live
   Windows: C:\content-fabric-live
   Папка создаётся при первом развёртывании; runner должен иметь право записи.
   Не выбирай папку _work или checkout репозитория.

ВКЛЮЧЕНИЕ

5. В GitHub Settings -> Secrets and variables -> Actions -> Variables добавь:
   CONTENT_FABRIC_DEPLOY_DIR = выбранный абсолютный путь на N100
   ENABLE_HOME_DEPLOY = true
   Это обычные Repository variables, не Secrets.
   До включения ENABLE_HOME_DEPLOY выполняются проверки и сборка, без обновления N100.

6. Запусти Actions -> CI and home deployment -> Run workflow, выбрав main,
   либо отправь новый commit в main. Runner должен быть Online.
   Образы собирает GitHub, а N100 только скачивает их и запускает.
   Отдельный постоянный GHCR-токен не нужен: workflow использует GITHUB_TOKEN.
   Приватные packages должны быть связаны с репозиторием и доступны этому workflow;
   образы публикуются с OCI source label для такой связи.

7. После первого успешного развёртывания открой http://localhost:5175 на N100
   или http://IP-N100:5175 из домашней сети. Зарегистрируй аккаунт и введи свои
   ключи Gemini/fal.ai/ElevenLabs в настройках приложения.
   Ключи остаются на сервере и в базе приложения, а не в GitHub.
   Скрипт создаёт .env с MAX_CONCURRENT_JOBS=1 и новым секретом хранения ключей.
   Повторные обновления этот .env сохраняют.

ОБНОВЛЕНИЯ И ДАННЫЕ

Обновление перезапускает backend/renderer. Выполняй его после завершения генераций:
текущие очереди и статусы активных задач хранятся в памяти процесса.
Чтобы временно отключить автоматические обновления, поставь ENABLE_HOME_DEPLOY=false.
Для включённого CI/CD сбой тестов или сборки останавливает выпуск.
Скрипт скачивает образы до замены контейнеров, ждёт healthcheck и при неудачном
обновлении пытается вернуть предыдущую конфигурацию и версию контейнеров.
Он не удаляет Docker-тома и не откатывает содержимое базы данных.

Постоянные Docker-тома: content-fabric-output и content-fabric-uploads.
Файлы в постоянной папке: .env, compose.yml, images.env.
Резервируй тома и .env вместе: секрет необходим для расшифровки сохранённых ключей.
Если раньше запускал ZIP через обычный docker-compose.yml, там другие имена томов:
перенос существующих аккаунтов/роликов требует отдельного экспорта/импорта данных.
Описанная установка создаёт отдельный экземпляр приложения.

CI/CD не открывает приложение в интернет. Для публичного доступа понадобится
отдельная настройка домена, HTTPS и доступа к домашней сети.

ПРОВЕРКИ

Workflow проверяет backend, frontend и скрипт обновления, затем собирает
три Linux/amd64-образа. Результаты проверок и сборки находятся на вкладке Actions.
Обновление N100 выполняется отдельным заданием после успешной сборки и только
при ENABLE_HOME_DEPLOY=true. Для первого запуска нужен зарегистрированный runner.

Локальная проверка скрипта обновления без Docker и внешних API:
python -m unittest discover -s deploy -p 'test_*.py' -v
